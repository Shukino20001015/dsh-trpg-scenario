# dsh-trpg-scenario

DeepSeek Harness 的 AI 跑团插件：导入剧本包、开局、评分。

## 装

目前为开发测试版本，尚未发布 npm 包或验证 GitHub 安装。测试包可通过 Desktop 的「插件 → 添加插件」输入本地 `.tgz` 路径安装；隔离 Web 环境也可使用：

```
dsh plugin --profile web add /绝对路径/测试包.tgz
```

按界面提示启用插件；若未显示，重启 DSH 后检查。开发测试包不是正式发布版。

## 用

| 命令 | 作用 |
|---|---|
| `/trpg list` | 列出已装剧本 |
| `/trpg import <zip>` | 导入一个剧本包 |
| `/trpg remove <名称>` | 删除剧本 |
| `/trpg play <名称>` | 兼容旧版的命令行开局；新界面建议使用「开一局」 |
| `/trpg judge <名称>` | 在独立会话中附上日志并准备评分 |

剧本库默认在 `~/.dsh/trpg/scenarios`。

新导入的剧本包含玩家不应提前查看的主持人底稿；在支持 POSIX 权限的系统上，新建剧本目录和文件默认仅允许当前用户访问。插件不会修改已有目录或旧剧本的权限；Windows 访问控制与共享设备隔离尚未验证。请勿向玩家分发剧本库或快照，而应由组织者管理原始剧本包。

## 剧本包格式

一个 ZIP，包含以下六个必需文件和可选的玩家须知：

```
manifest.yaml    id / title / kind / minutes
system.md        玩法与规则
setting.md       背景、角色、初始困境
opening.md       开场场景
player.md        玩家可见的世界、角色关系和玩法说明（可选；新剧本建议提供）
criteria.json    玩家可见的评分维度（可选）
score-bands.json 评委数值档位，用于辅助核验（可选）
stages.json      阶段网络与总体目标（可选；阶段化剧本使用）
character.json   主角状态字段与初值（可选；须配合 stages.json）
rubric.md        评分维度（每维 0–10）
judge.md         评委系统提示词
```

六个必需文件缺一不可；不提供 `player.md` 的旧剧本仍可导入，但不会把可能包含秘密的 `setting.md` 当作玩家简介展示。可选的 `criteria.json` 单独保存玩家可见的评分维度：3–6 项，每项为 `{"name":"维度名称","description":"简短解释"}`；维度名称不超过 50 字符，说明不超过 200 字符，名称不得重复。必须由剧本作者核对其与 `rubric.md` 一致且不含剧透。没有公开维度的旧剧本会提示组织者补充，不自动展示可能包含底牌的评分表。公开维度发生变化会改变版本摘要，同一次活动请使用相同版本。

阶段化剧本的 `stages.json` 提供总体目标、阶段与允许转换的条件。玩家界面只展示目标、当前和已确认走过的阶段；未来阶段及条件不公开。主持模型按对话事实申请转换，程序检查路线、当前版本和原文引用，但无法保证引用在语义上真正证明条件，也不能保证模型总会及时调用；阶段不一致时以对话为准并由组织者核对。各组仍独立游玩，线下时间由现场主持人掌握。

本开发测试包默认启用实验性的阶段与主角状态自动判断：需要剧本提供对应配置，玩家正常描述行动即可，不需要请求更新卡片。后台会使用所选或默认模型提取和复核，可能产生额外模型调用、费用和延迟；卡片更新也可能遗漏或有误，请以实际对话为准并使用界面纠错。关闭后台判断可在 DSH 的插件配置中将 `experimentalAutoStage` 和 `experimentalAutoCharacter` 设为 `false`；这不会关闭模型主动调用状态工具。要禁用主角状态功能可将 `experimentalCharacter` 设为 `false`，但包含主角状态配置的剧本将无法开局。已有安装的插件配置可能保留旧设置，应检查实际配置；这些功能尚待完整真实试玩和人工验收。

阶段误切的直接纠正为默认关闭的实验功能，仅供隔离测试：插件配置 `experimentalStageCorrection: true` 时，新开阶段局使用独立的 V2 快照契约，主持可引用后续对话申请纠正最近一次转换并接受额外模型审核。旧局继续使用原快照和原工具契约；更改开关会改变阶段剧本的新局版本摘要。纠错可能被拒绝、延迟或判断错误，模型审核不能代替人工核对。单局分段评分支持核对 V2 日志；普通多局评分可以接收同版 V2 日志，但仍是一次性评分，不具备分段处理，长记录及输出中断须人工核查。同一次比较中已识别的版本必须一致，缺少版本的旧记录需人工确认。V2 在隔离 macOS DSH 与真实模型有一次纠正和重启成功样本；中断、跨设备和 Windows 尚待验证，不应当作正式活动已验收功能。

## 上下文怎么进

插件为游玩和评分分别创建新的「AI 跑团」专用会话。游玩的规则、背景与开场写入该会话的系统上下文；评分会话单独载入剧本的评委规则和评分标准。已有聊天或工具记录的会话会拒绝重复初始化。

通过卡片创建的会话会先设置中性标题，避免 DSH 的自动命名功能把对话额外发送给命名模型。游玩内容仍会发送给你选择的游玩模型，评分日志仍会发送给你选择的评委模型；请在上传前检查个人信息和模型服务商。

长对话可在跑团会话中使用 DSH 的 `/compact` 压缩上下文，压缩过程会把相关对话发送给所用模型服务；使用前请确认服务商与隐私要求。压缩摘要可能遗漏或改变事实，不能代替人工核对；评分前仍应导出并检查原始会话记录。该能力目前仅在隔离的 macOS Desktop 和模拟模型上验证，真实模型的摘要质量尚未验证。

## 限制

- macOS Desktop 已用独立测试配置验证界面安装、剧本选择、固定开场、模拟模型游玩与独立评分请求，以及重启后恢复；这些验证不能证明真实模型的评分质量或多人活动体验
- 真实模型已完成少量多轮游玩和独立评分测试，但出现过人数、时间和计算前后不一致，也曾把剧本中有条件才可能出现的承诺写成已经发生；评委也曾未识别这类错误。提示词不能保证避免这些问题，评分须人工对照原始记录；Windows 已进行隔离的少量真实模型试玩与评分，真实多人活动尚未验证，不应当作稳定评分工具
- 同名剧本导入不会覆盖已有内容
- 评分目前只提取导出日志中的玩家与主持文本。阶段化剧本会核对并过滤本插件的阶段工具调用和结果，不把它们当玩家对话；其他工具、图片或附件会停止自动评分并要求人工核对，避免遗漏证据。过长日志也不会静默截断
- 新开局会记录剧本、玩家须知和评分规则的版本摘要，评分时发现摘要不一致会拒绝；旧日志即使含游玩规则，也可能没有当时评分规则的版本摘要，此时需人工核对，确认可比前评委被要求不排名。这不能证明日志未被修改或完整，也不替代组织者冻结和核对规则；模型遵守提示也不能得到绝对保证
- 升级插件也可能改变通用主持或评委规则并使新旧版本不可比；同一次活动请冻结插件和剧本版本，评分完成并导出日志后再升级。早期测试会话可能需要原版本插件与原剧本才能继续或评分
- 同一日志若出现不同版本的游玩规则，停止自动评分并要求人工核对；相同规则在不同轮次重复出现可以接受
- DSH 的会话依赖插件提供的 `trpg` 会话预设；卸载或禁用插件后，相关会话可能无法重新打开。请先导出日志，并在需要恢复时重新启用兼容版本的插件
- 跑团会话如果在初始化时中断，导致已保存的规则缺失，将拒绝安全恢复；请重新开局或重新创建评分会话，而不要把该会话当作正常结果
- Windows DSH 0.2.2 已进行隔离安装、少量真实模型游玩、重启和一次评分测试；更长游玩及其他版本尚未覆盖

## 玩法

可以单人游玩，也可以多人共用设备游玩。多人分组时，各组各用一台设备独立游玩同一版剧本；实际时间由现场主持人约定和把控。游玩后导出会话日志，新建独立评委会话评分；评委也可以使用另一台设备。

新会话选择「AI 跑团」模式后，输入框上方显示跑团操作区；标准等其他模式不显示。开始对话后操作区收起，可点击展开：

1. 导入 ZIP 并选择剧本；点「开一局」→ 创建独立的游玩会话并载入剧本
2. 新会话先显示玩家须知和固定开场；同一版本剧本的各局使用相同开场原文，直接输入第一步行动
3. 模型根据已载入的剧本回应。游玩后用会话菜单导出日志，在跑团操作区选择剧本，点击“上传对话日志评分”创建独立评委会话；一份日志可单独评分，也可上传多份进行比较。带完整开局记录的日志会尝试匹配已导入的原剧本；原剧本未导入时请先导入，版本摘要或规则不一致仍会拒绝评分。旧日志无法识别时沿用所选剧本并提示核对。

评分前，组织者只有在逐份核对所选记录覆盖对应的整局游玩时，才勾选“已核对”选项；不确定时保持未勾选，仍可让评委分析已见内容。勾选只向评委传达人工声明，不是插件自动验证，也不能证明日志未被修改；版本不一致仍会被拒绝，缺乏可比证据的记录仍需复核。评委可能忽略约束或给出不合理分数，最终结果须对照原始记录和标准由人核对。

尚未输入行动的开局可能不会出现在 DSH 的普通历史列表中；可在跑团操作区的「继续尚未行动的跑团」找到。入口通过已保存的开局记录识别，而非依赖会话名称；首次行动后可在 DSH 历史列表中找到会话。

开局和评分前，可使用当前会话的模型选择器选择模型；新建的跑团或评分会话会沿用这一选择，因此评委也可以使用不同于游玩的模型。

点击后会自动创建并打开新的独立会话，无须手动新建。

## 它怎么工作

卡片创建独立会话并载入冻结版本的规则、背景和开场。固定开场直接显示，不额外伪造用户消息或调用模型生成新开场；首次模型调用发生在玩家提交行动时。评分另开会话并导入原始日志。

新开局会在本机剧本库的 `.snapshots` 中保存受版本摘要校验的原剧本及规则快照，含主持人隐藏设定，文件使用仅当前用户可读写的权限。首次行动前重启或原剧本被修改时，可尝试从该快照恢复；快照缺失、损坏或版本无法校验时不会擅自切换规则。旧版开局没有快照时仍沿用原有的保守恢复方式。快照不会随对话日志导出或自动同步：组织者可从游玩会话下载原局快照 JSON，并在可信评委设备的跑团卡片导入；对话日志仍须另外导出。快照包含隐藏设定，只应交给可信评委，摘要只能匹配版本，不能证明文件来源或日志真实完整。删除已导入的剧本不会删除旧局快照。

卡片上的“分段评分”可一次选择最多 6 份日志，每份独立创建任务；任务列表以文件名和会话编号区分，某份失败不影响其他任务，不自动合并成绩或排名。若启动结果未知，请先检查任务，勿重复提交。每份先校验原局快照或与原局摘要完全一致的已安装版本，再分段提取候选证据，并对每个维度复核完整对话。使用当前选择或 DSH 默认模型，过程会多次发送对话和评委所需的剧本资料，可能增加耗时和费用。任何分段或维度失败都不返回部分成绩；混合工具文本是否展示未知时不会计算总分。草稿会按措辞提示可能包含玩家更正或否认的记录编号；该提示可能漏报或误报，不自动认定事实或修改分数。草稿的引文、档位和反证仍须由组织者对照原始日志人工核查，不能将机器检查视为语义正确。隔离 macOS 和 Windows 已分别完成少量真实 Flash 评分，长日志覆盖、证据准确性和费用尚未全面验收；模型可能提及玩家尚未遇到的情节，报告仅供组织者审阅。 评分在后台运行；可通过“组织者：分段评分任务”查看进度和重新打开结果；列表有运行中任务时自动刷新，窗口重新可见时也会刷新。已完成的草稿与任务状态保存在本机剧本库的 `.segmented-jobs` 目录，包含可能敏感的内容。进程中断后任务不会自动从断点继续，须保留原日志并在新会话重新评分；状态为“需检查”时应先确认原进程是否仍在运行。 评分任务会话仅用于查看进度和报告；如需新游戏或新评分，请使用“返回评分入口”另建会话，不要在任务会话发送普通消息。

玩家须知和固定开场支持 Markdown 标题、强调、列表、引用、表格、代码及安全链接；原始 HTML 只当文字显示，图片不会自动加载。

开发时请编辑 `client.source.js` 与 `markdown-renderer.js`，运行 `node build-client.mjs` 生成实际加载的 `client.js`；`node build-client.mjs --check` 可检查生成文件是否同步。Markdown 解析器为随源码保留许可证的 Marked。

## 已知取舍

- 剧本规则作为系统上下文保存，不作为一个独立的可编辑界面卡片
- 当前界面通过 owner 鉴权的只读接口读取剧本目录和开场；兼容旧版的手动命令仍可能在对话轨迹中显示输出
- 普通游玩和评委会话不暴露跑团状态工具；阶段化游玩会话暴露阶段工具，配置了主角状态时还暴露主角状态工具。工具隔离曾在 macOS Desktop 与真实／模拟请求中检查，Windows 未全面验证，不应当作安全沙箱
- 阶段工具运行中若结果丢失且记录能核对，插件可暂停阶段工具并保留对话；此时界面提示阶段追踪不可用，后续不再受阶段门禁保护。旧阶段局缺少冻结的阶段规则时同样暂停，不能把它与新版本自动混评
- 新开局提示主持将工具调用与剧情回复分开发送；若人物状态工具发现同条消息混有可能未显示的叙述，会拒绝写入并提示继续回应玩家。这依赖模型遵守提示，不能保证消除重复或工具失败；旧局仍使用快照中冻结的规则。此次规则调整会改变阶段或人物状态剧本的版本摘要，同一次活动应继续冻结插件版本，旧日志评分需使用可核对的原版规则。
- 实验性 `/trpg audit` 可在独立评分会话中核查报告末尾的结构化评分块：使用开评时保存的剧本档位和各组记录编号，检查维度、分数、引用编号及加总；缺少依据或结构化结果时提示人工复核。对于分组和维度能可靠识别的部分报告，还可提示文字结论与结构化结果的明显冲突，但不能识别所有格式和矛盾。它不判断档位是否适用于玩家行为、引用是否支持结论，也不能阻止模型先在会话中展示错误结果。正式评分仍需人工复核；真实模型稳定性尚未验证。
- 核验评分时，若当前回合仍在运行、被中止、失败或达到输出上限，即使已经出现结构化评分块，也不能视为完整报告；旧记录缺少回合结束状态时会提示人工确认。该检查不能防止模型先输出不完整文字，也不能保证重新评分一定成功。
- 当评委原始请求和玩家角色编号可完整核对时，审计还会对少量能够识别的“归属于玩家的引文”做逐字比对；未找到时只提示人工复核，可能是转述、代写或引文截取差异，不自动判错或修改分数。多组边界不明、混合引用、代词或未被识别的表达不会被强行判断；没有提示不代表评委没有张冠李戴。
- 剧本包可选的 `score-bands.json` 是实验性的结构化数值档位：数组每项含 `name` 与 `bands`（每档为 `min`、`max`），名称必须与 `criteria.json` 完全对应，数值范围不可重叠；它参与版本校验。导入只能检查格式，不能证明其与 `rubric.md` 的文字条件一致，仍须剧本作者逐项核对；旧剧本无需提供该文件。
